# 개인정보 마스킹 (`src/utils/masking`)

서버(→ OpenRouter LLM)로 대화 내용을 보내기 **전에 기기에서** 개인정보를 자리표시로 바꾸는 모듈입니다.
외부 의존성 없이 정규식 규칙만으로 동작합니다.

```ts
import { maskPii, unmaskPii } from "../utils/masking";

const masked = maskPii("민수야 내 번호 010-1234-5678", { names: ["김민수", "민수"] });
masked.text; // "[이름1]야 내 번호 [전화번호1]"   ← 서버로는 이것만 보낸다
masked.mapping; // { "[이름1]": "민수", "[전화번호1]": "010-1234-5678" } ← 기기에만 둔다

unmaskPii(llmReply, masked.mapping); // LLM 답장 후보에 남은 자리표시를 원래 값으로 되돌린다
```

- 같은 값은 같은 번호를 받습니다(`[이름1]`이 두 번 나오면 같은 사람). LLM이 문맥을 잃지 않습니다.
- `mapping`은 원문 개인정보 그 자체이므로 **절대 서버로 보내지 않습니다.**

## 찾는 것

| 종류 | 자리표시 | 방식 |
|---|---|---|
| 주민등록번호(외국인 포함) | `[주민등록번호N]` | 날짜 검사 + 체크섬, 가린 뒷자리도 |
| 전화번호 | `[전화번호N]` | 01X·지역번호·070·050X, +82, 괄호 표기 |
| 이메일 | `[이메일N]` | 한글 로컬 파트 허용 |
| 주소 | `[주소N]` | 시/도·축약형·시/군·구 앵커 → 번지·건물·동/호까지 |
| 카드번호 | `[카드번호N]` | 그룹 구조 + Luhn |
| 계좌번호 | `[계좌번호N]` | 계좌 문맥어·은행 이름이 근처에 있을 때만 |
| 사업자등록번호 | `[사업자등록번호N]` | 국세청 체크섬 |
| 여권·운전면허 | `[여권번호N]`·`[운전면허N]` | 형식 + 지역코드 |
| 생년월일 | `[생년월일N]` | "생일/생년월일/…생" 단서가 있는 날짜만 |
| 이름 | `[이름N]` | **`names`로 넘긴 이름만** (사용자 본인·친구·대화 상대) |

전각 숫자, 폭 없는 공백, 대시 변형, 분해된 자모, 숫자 사이 가운뎃점(`010·1234·5678`)처럼
표기를 비틀어도 정리본에서 한 번 더 찾아 원문 위치로 되돌립니다.

## 출처와 라이선스

이름을 뺀 탐지 규칙은 [maskingtape](https://github.com/ChoHyeonChan/maskingtape)
(Apache-2.0, 커밋 `26d41ab`)의 규칙 탐지기를 TypeScript로 옮긴 것입니다. 라이선스 전문은
[LICENSE-maskingtape](./LICENSE-maskingtape)에 있습니다.

원본과 달라진 점:

- 규칙 이름 탐지기(`name.py`)와 LLM 이름 탐지기는 옮기지 않고, 서비스가 아는 이름 사전으로 대신합니다(`detectors/name.ts`).
- 파이썬 정규식의 조건부 참조 `(?(1)…)`는 두 갈래 정규식으로, `pos/endpos` 인자는 `regex.ts` 도우미로 바꿨습니다.
- 자모 합치기는 `String.prototype.normalize` 대신 한글 음절 조합 공식으로 직접 합니다.
- 위치는 UTF-16 기준입니다(JS 문자열과 같음).

옮긴 뒤 원본 파이썬 구현(이름 탐지기 제외)과 결과를 대조했습니다. maskingtape 테스트 문자열 2,230개와
벤치마크 문서 2,580개에서 탐지 구간과 종류가 모두 같았습니다. 실제로 만들어지는 정규식 67개는
Hermes 컴파일러(`hermesc`)로 문법을 검사했습니다.

원본 규칙을 고치는 업스트림 변경이 생기면 해당 탐지기 파일을 같은 방식으로 다시 옮기면 됩니다.
