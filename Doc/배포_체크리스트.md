# 백엔드 배포 체크리스트

## 1. 컨테이너로 실행 (로컬 확인 완료)
```
cd Src/Back
cp .env.example .env   # 값 채우기 (아래 2번 참고)
docker compose --profile app up -d --build
```
- `postgres`는 기본으로 뜨고, `backend`는 `--profile app`을 붙일 때만 뜬다. 개발 때는 기존처럼 `docker compose up -d`로 DB만 띄우고 `npm run start:dev`를 쓴다.
- 컨테이너 안에서는 `DB_HOST=postgres`, `DB_SYNCHRONIZE=false`, `DB_MIGRATIONS_RUN=true`, `TRUST_PROXY=1`로 덮어쓴다. 서버가 시작할 때 마이그레이션이 자동 적용된다.
- `--profile app`에는 `caddy`(HTTPS)도 함께 뜬다. `.env`의 `DOMAIN`에 서버 도메인을 넣으면 인증서를 자동으로 받는다. 이때 80, 443 포트가 인터넷에 열려 있어야 한다(Azure NSG).
- **백엔드(5010)는 호스트에 열지 않는다.** 외부에서는 caddy(80/443)로만 들어온다. DB(5432)는 서버 자신(127.0.0.1)에서만 접속된다.
- 이미지는 멀티스테이지(Node 22 alpine)이고 비루트(`node`) 사용자로 실행된다.
- 이미지 안의 npm은 `Dockerfile`의 `ARG NPM_VERSION`(지금 11.12.1)으로 고정한다. Node 22 기본 npm(10)은 npm 11로 만든 `package-lock.json`을 거부해서 서버 빌드가 깨진 적이 있다(#64). npm 11은 npm 10·11 어느 쪽으로 만든 lockfile도 받아들인다.
- `postgres`, `backend`, `caddy` 모두 `restart: unless-stopped`라서 서버(VM)나 Docker가 다시 켜지면 자동으로 다시 켜진다. `docker compose stop`처럼 직접 멈춘 컨테이너는 다시 켜지지 않는다.

## 1-1. 서버 배포: `deploy.sh` 한 번으로
처음 한 번은 스크립트를 받기 위해 직접 pull 하고, 그다음부터는 스크립트만 실행한다.
```
cd ~/<레포 폴더>
git pull --ff-only https://github.com/CSID-DGU/2026-2-OSSProj-PING-02.git main   # 처음 한 번만
bash Src/Back/scripts/deploy.sh
```
스크립트가 하는 일 (`Src/Back/scripts/deploy.sh`):
1. **사전 점검:** Docker 실행·부팅 자동 시작, `.env`의 `JWT_SECRET`·`DB_PASSWORD`·`DOMAIN`(값은 출력하지 않음), 서버에서 직접 고친 파일이 없는지. DB 비밀번호 기본값, AI 키 누락, `AI_PROVIDER` 오타는 경고만 한다.
2. **코드 받기:** 팀 레포 `main`을 `git pull --ff-only` (서버의 remote 이름과 상관없음)
3. **이미지 빌드:** 실패하면 여기서 멈춘다. **돌고 있는 컨테이너는 바꾸지 않으므로 서비스는 이전 버전으로 계속 동작한다.**
4. **교체:** `docker compose --profile app up -d`
5. **확인:** backend healthy(최대 120초), `/v1/app/version` 응답, 세 컨테이너가 `running`·`unless-stopped`인지

- 실패하면 원인과 되돌리는 명령(`git reset --hard <이전 커밋>` 후 `DEPLOY_SKIP_PULL=1 bash ...`)을 출력한다. 자동으로 되돌리지는 않는다.
- 옵션(환경변수): `DEPLOY_SKIP_PULL=1`(받지 않고 지금 코드로 다시 빌드, 예: `.env`만 바꿨을 때), `DEPLOY_BRANCH`, `DEPLOY_REPO_URL`, `DEPLOY_HEALTH_TIMEOUT`
- 위 1번의 수동 명령(`up -d --build`)도 그대로 쓸 수 있다. 다만 빌드가 실패했는지 직접 확인해야 한다.

## 1-2. 의존성을 바꿀 때 (package.json)
`package.json`을 바꾸면 lockfile을 Docker의 npm으로 다시 만든다. PC의 npm 버전과 상관없이 같은 lockfile이 나온다.
```
bash Src/Back/scripts/update-lockfile.sh   # Docker 필요. Windows는 Git Bash에서 실행
```
- Node 22 기본 npm(10)으로 lockfile을 만들고, npm 10과 `Dockerfile`의 npm 양쪽에서 `npm ci`가 되는지 확인한다.
- lockfile에 이미 적힌 패키지 버전은 올리지 않는다. 끝나면 `git diff --stat Src/Back/package-lock.json`으로 바뀐 줄을 보고 `package.json`과 같이 커밋한다.

## 2. 운영 환경변수
| 변수 | 운영 값 |
|---|---|
| `NODE_ENV` | `production` (Swagger 비노출) |
| `JWT_SECRET` | 32자 이상 랜덤 값. 예: `openssl rand -base64 48` |
| `DB_SYNCHRONIZE` | `false` |
| `DB_MIGRATIONS_RUN` | `true` |
| `DB_PASSWORD` | 기본값(`malssiat`) 사용 금지. `.env` 한 곳만 바꾸면 compose의 DB 비밀번호도 같이 바뀐다. **DB 볼륨을 처음 만들 때 정해진 값이 유지되므로, 첫 실행 전에 바꿔야 한다.** 예: `openssl rand -base64 24` |
| `MAIL_*` | 아이디·비밀번호 찾기 메일을 보낼 SMTP 정보. Gmail 앱 비밀번호는 하루 약 500통 제한이 있어 시연용으로만 적합 |
| `DOMAIN` | HTTPS용 도메인 (예: `malssiat.koreacentral.cloudapp.azure.com`) |
| `TRUST_PROXY` | compose가 `1`로 넣는다(앞단 caddy 1개). 프록시 없이 직접 노출할 때는 `0` |
| `MODEL_CDN_BASE_URL` | 실제 모델 파일 주소 (현재 URL 서명 없음) |
| `OPENROUTER_API_KEY` | AI 답장용 OpenRouter API 키. **운영 서버 `.env`에만** 둔다. 비어 있으면 `/v1/ai/reply`만 503 |
| `AI_MODEL` | 사용할 모델 ID. ZDR 엔드포인트가 있는 모델이어야 한다 |
| `AI_TIMEOUT_MS`, `AI_MAX_OUTPUT_TOKENS` | 기본 30000, 1500 (#65, 답장 9개). **서버 `.env`에 예전 값 20000, 400이 남아 있으면 고친다** |
| `AI_MAX_INPUT_CHARS`, `AI_RATE_PER_MINUTE`, `AI_RATE_PER_DAY` | 기본 1000자, 분당 10회, 하루 300회 (임시값) |
| `AI_PROVIDER` | 비우면 주 통로(OpenRouter). 보조(테스트용) Claude API 를 쓸 때만 `anthropic` (아래 "선택: Claude API로 테스트할 때") |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | `AI_PROVIDER=anthropic`일 때만 필요. 키는 **운영 서버 `.env`에만** 둔다 |

## 3. 배포 전 확인
- [ ] `.env`가 저장소에 올라가지 않았는지 (`.gitignore`, `.dockerignore` 적용됨)
- [ ] 배포는 `bash Src/Back/scripts/deploy.sh`로 하고, 마지막에 `배포 완료`가 나왔는지 (1-1)
- [x] 5432 포트를 외부에 열지 않았는지 (compose가 `127.0.0.1`에만 연다. Azure NSG에서도 5432를 열지 않는다)
- [x] 백엔드 5010을 호스트에 열지 않았는지 (compose에서 제거함. NSG에서도 열지 않는다)
- [ ] `DB_PASSWORD`를 기본값이 아닌 값으로 바꿨는지 (첫 실행 전에)
- [ ] HTTPS: compose에 caddy를 넣었다. 서버에서 `DOMAIN`을 정하고 80/443을 열면 인증서가 자동 발급된다. Android는 기본으로 http 통신을 막는다.
- [ ] 서버가 켜질 때 Docker도 자동으로 켜지는지 (`sudo systemctl enable docker`)
- [ ] 서버를 재부팅한 뒤 `docker compose --profile app ps`에서 `postgres`, `backend`, `caddy`가 모두 Up인지
- [ ] Azure VM의 자동 종료(Auto-shutdown) 설정이 꺼져 있는지 (켜져 있으면 정해진 시각에 서버가 꺼짐)
- [ ] DB 볼륨(`malssiat-pg`) 백업 방식 결정
- [ ] 모델 다운로드 URL 서명/저장소 방식 결정
- [ ] OpenRouter 계정의 개인정보 설정에서 **"ZDR only"** 를 켰는지 (켜지 않으면 Safety Retention 업체가 허용될 수 있음. https://openrouter.ai/settings/privacy)
- [ ] OpenRouter API 키에 **사용 한도**를 걸었는지 (비용 사고 방지. 서버 코드에는 전체 일일 상한이 없음)
- [ ] 정한 모델이 ZDR 목록(`https://openrouter.ai/api/v1/endpoints/zdr`)에 있는지
- [ ] 실제 키로 `/v1/ai/reply`를 한 번 호출해 200을 받았는지 (지금까지는 가짜 서버로만 검증)
- [ ] 서버 로그(`docker compose logs backend`)에 메시지 본문이 남지 않는지 눈으로 확인
- [ ] 외부 AI 전송 동의 약관(`AI_TRANSFER`) 문구·필수 여부를 법률 검토 후 확정했는지

## 4. 선택: Claude API로 테스트할 때 (보조 통로)
OpenRouter 준비 전에 팀 내부 테스트용으로 쓰는 보조 통로다. 앱과 API 요청·응답 형식은 같다.
```
# 운영 서버 Src/Back/.env 에 추가
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=발급받은_키
ANTHROPIC_MODEL=claude-sonnet-5-5

# 새 의존성이 들어간 버전을 처음 배포할 때는 --build, 이후 .env 만 바꿀 때는 up -d (restart 는 .env 를 다시 읽지 않음)
docker compose --profile app up -d --build
```
- [ ] Claude Console(platform.claude.com)에서 API 키에 **월 사용 한도**를 걸었는지 (서버 코드에는 전체 일일 상한이 없음)
- [ ] 실제 사용자 데이터가 아니라 **팀 내부 테스트 대화**로만 쓰는지. Claude 통로는 OpenRouter 처럼 요청마다 데이터 미보관(ZDR)을 강제하지 않고, 약관의 받는 곳에도 아직 없다 (`Doc/약관_초안_AI전송.md` 검토자에게 7번)
- [ ] 서버 로그(`docker compose logs backend`)에 `알 수 없는 AI_PROVIDER` 경고가 없는지 (오타면 AI 요청이 503)
- [ ] 테스트가 끝나면 `AI_PROVIDER`를 비우고 `docker compose --profile app up -d`로 OpenRouter 로 되돌렸는지
