# 백엔드 배포 체크리스트

## 1. 컨테이너로 실행 (로컬 확인 완료)
```
cd Src/Back
cp .env.example .env   # 값 채우기 (아래 2번 참고)
docker compose --profile app up -d --build
```
- `postgres`는 기본으로 뜨고, `backend`는 `--profile app`을 붙일 때만 뜬다. 개발 때는 기존처럼 `docker compose up -d`로 DB만 띄우고 `npm run start:dev`를 쓴다.
- 컨테이너 안에서는 `DB_HOST=postgres`, `DB_SYNCHRONIZE=false`, `DB_MIGRATIONS_RUN=true`, `TRUST_PROXY=1`로 덮어쓴다. 서버가 시작할 때 마이그레이션이 자동 적용된다.
- `--profile app`에는 `caddy`(HTTPS)도 함께 뜬다. `.env`의 `DOMAIN`에 서버 도메인을 넣으면 인증서를 자동으로 받는다. 이때 80, 443 포트가 인터넷에 열려 있어야 한다(Azure NSG).
- **백엔드(5010)는 호스트에 열지 않는다.** 외부에서는 caddy(80/443)로만 들어온다. DB(5432)는 서버 자신(127.0.0.1)에서만 접속된다.
- 이미지는 멀티스테이지(Node 22 alpine)이고 비루트(`node`) 사용자로 실행된다.

## 2. 운영 환경변수
| 변수 | 운영 값 |
|---|---|
| `NODE_ENV` | `production` (Swagger 비노출) |
| `JWT_SECRET` | 32자 이상 랜덤 값. 예: `openssl rand -base64 48` |
| `DB_SYNCHRONIZE` | `false` |
| `DB_MIGRATIONS_RUN` | `true` |
| `DB_PASSWORD` | 기본값(`malssiat`) 사용 금지. `.env` 한 곳만 바꾸면 compose의 DB 비밀번호도 같이 바뀐다. **DB 볼륨을 처음 만들 때 정해진 값이 유지되므로, 첫 실행 전에 바꿔야 한다.** 예: `openssl rand -base64 24` |
| `MAIL_*` | 아이디·비밀번호 찾기 메일을 보낼 SMTP 정보. Gmail 앱 비밀번호는 하루 약 500통 제한이 있어 시연용으로만 적합 |
| `DOMAIN` | HTTPS용 도메인 (예: `malssiat.koreacentral.cloudapp.azure.com`) |
| `TRUST_PROXY` | compose가 `1`로 넣는다(앞단 caddy 1개). 프록시 없이 직접 노출할 때는 `0` |
| `MODEL_CDN_BASE_URL` | 실제 모델 파일 주소 (현재 URL 서명 없음) |

## 3. 배포 전 확인
- [ ] `.env`가 저장소에 올라가지 않았는지 (`.gitignore`, `.dockerignore` 적용됨)
- [x] 5432 포트를 외부에 열지 않았는지 (compose가 `127.0.0.1`에만 연다. Azure NSG에서도 5432를 열지 않는다)
- [x] 백엔드 5010을 호스트에 열지 않았는지 (compose에서 제거함. NSG에서도 열지 않는다)
- [ ] `DB_PASSWORD`를 기본값이 아닌 값으로 바꿨는지 (첫 실행 전에)
- [ ] HTTPS: compose에 caddy를 넣었다. 서버에서 `DOMAIN`을 정하고 80/443을 열면 인증서가 자동 발급된다. Android는 기본으로 http 통신을 막는다.
- [ ] DB 볼륨(`malssiat-pg`) 백업 방식 결정
- [ ] 모델 다운로드 URL 서명/저장소 방식 결정
