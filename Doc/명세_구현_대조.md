# 명세·ERD와 백엔드 구현 대조 결과

> 백엔드(`Src/Back`) 구현을 API 명세, ERD, 아키텍처 문서와 엔드포인트·테이블·컬럼 단위로 대조한 결과입니다.
> 차이가 있는 곳과 그 처리 상태만 적었습니다. 명세 원문(PDF)은 이 저장소에 없어서 줄 번호는 텍스트로 옮긴 파일 기준입니다.

## 1. 처음 대조에서 확인한 차이

| # | 항목 | 명세 | 구현 | 판정 | 처리 |
|---|---|---|---|---|---|
| 1 | 입력 검증 | 절대 규칙 1: `whitelist`와 `forbidNonWhitelisted` 유지 | `app.setup.ts`에 `whitelist: true`만 있었음 | 실제 차이 | **적용함.** `forbidNonWhitelisted: true`를 추가했고, DTO에 없는 필드(예: `messageText`)는 400 `VALIDATION_FAILED`로 거부한다. e2e로 확인 |
| 2 | 모델 다운로드 URL | 만료되는 서명 URL, Range 지원 | `model-storage.service.ts`에서 서명 없이 `${base}/${key}`로 생성 | 실제 차이 | **보류.** 서명 URL과 공개 CDN 중 팀 결정 필요. 모델 배포를 제외한 상태 |
| 3 | `users.deleted_at` | ERD에 있음. 즉시 삭제로 정하면 사용하지 않는다고 주석 | 컬럼 없음, 탈퇴 시 즉시 삭제 | 충돌 없음 | ERD 원본과 중간보고서 3-2(탈퇴 시 `deleted_at` 기록)는 **직접 고쳐야 함** |
| 4 | 테이블 수 | 아키텍처 §8은 4개, ERD는 7개 | 구현은 ERD를 따름 | 문서 차이 | 아키텍처 문서 정리 필요 |
| 5 | 예시 사용자 ID | API 명세 예시 `u_123` | ID는 UUID | 예시 문제 | `Doc/API_목록.md`에 UUID임을 명시. 명세 예시도 고치는 것을 권장 |
| 6 | 모델 롤아웃 | `rollout_percent`로 단계 배포 | `models.service.ts`에 해시 버킷으로 구현됨 | 차이 없음 | 처음 의심했으나 구현되어 있었음 |

## 3. 일치를 확인한 항목

- 엔드포인트 경로와 메서드, 에러 코드와 HTTP 상태
- 토큰 정책: 액세스 30분, 리프레시 30일, 회전, 재사용 감지 시 해당 기기 세션 폐기
- ERD 7개 테이블의 이름과 주요 컬럼
- 탈퇴 시 비밀번호 검증 (누락 400, 불일치 401)
- 로그인 실패 시 아이디 존재 여부를 드러내지 않는 같은 오류 응답

## 4. 남은 결정 사항

- 모델 다운로드 URL 방식(서명 URL 또는 공개 CDN)과 저장소 (#2)
- ERD 원본, 중간보고서, 아키텍처 문서의 `deleted_at`·테이블 수·예시 ID 정리 (#3, #4, #5)
- 아이디 로그인, 가입 시 이메일 미인증, 아이디·비밀번호 찾기를 명세에 반영할지 (#13~#16)
- 서버 데이터 백업 정책
